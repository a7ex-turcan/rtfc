description: Show this project's source subscriptions (Jira, Confluence and Bitbucket notifications polled into the inbox) and their health.
---
Call the rtfc `sources` tool and show the user what it returns: for each subscription its account, type, selector, events, mode, status, how far it has read, the next poll and any error. If a subscription is `pending_approval`, say that `/rtfc:sources-approve` lets it start polling. If there are none, explain in two sentences how to add one: an account with `rtfc account add <name> --type jira|confluence|bitbucket --url <site or https://api.bitbucket.org> --login <email>` in a terminal, then a `sources` entry in this project's `.claude/rtfc.local.json` with that account and a `jql` (Jira), an optional `space` (Confluence) or a `repo` (Bitbucket, `workspace/slug`), then `/rtfc:sources-approve`. A feed (a command that prints JSON, for apps with no adapter) is added with `rtfc account add <name> --type feed`, which asks for the command in the terminal, or with `--stream` for a command that keeps running and prints a line per change, which arrives in seconds rather than at the next poll; its subscription only names the account, and the command never goes in the file. If the user asks how to hear about every pull request a teammate opens in a Bitbucket repository, not only the ones they review, say that adding `opened` to that subscription's `events` list does it: it is opt-in, a subscription without `events` never gets it, and the edited entry needs `/rtfc:sources-approve` again. If a subscription shows an error about a refused token, say that `rtfc account add` in a terminal stores a new one. Do not run any rtfc commands and do not edit the file unless the user asks.
